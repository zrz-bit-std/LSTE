# Place 内完整探索与 DFS 验收

目标：现有 GP/SLAM 门洞候选、去重、单门认证动作保持原语义；认证后跨门才建立或绑定 Place。
根分岔口按语义优先级选择分支。Place 内仅派发属于当前空间的 WI，并执行开放 TSP；
动态 frontier 前移必须持续产生待办，不以已完成支持区的重叠吞掉仍未观察的远处区域。

进入子 Place 必须有认证 Portal 及真实跨门证据。新子 Place 优先于父 Place 剩余 WI；
使用 DFS 栈记录父子和入口，子节点完成后经原 Portal 回父节点，继续父节点剩余 WI/子节点。
父 Place 只有在本地待办与所有子节点完成后才关闭；已关闭空间不得再生成 WI 或作为
探索目标重入，但祖先的未完成空间必须仍可用于返回。全部空间统一按 Place 管理，不加入
走廊/房间类别或连续狭窄空间判断。WI 归属由在线 SLAM 和认证门洞边界共同给出。

必须逐项证明：Portal 和 Place 绑定正确；同一 Place 的可执行 WI 按 TSP 实际派发；
动态 WI 持续处理；子 Place 推栈早于父节点后续待办；有深度至少 2 的真实嵌套轨迹；
回溯顺序正确；父子未完成时禁止关闭；原根分支顺序保持；冻结 WI 恢复；四场景真实完成。
原有审计不足以证明这些条件，需要新增空间归属、DFS 栈、完成证据与回溯审计。
测试与可视化仅使用真实 ROS/SLAM/里程计数据，不能用合成日志代替四个 Gazebo 场景。

证据放 runtime/gp_branch_development/place_dfs_20261025，两个 1024 最终成功包保持原样。

### 已观测旧 WI 的证据消解

持续映射可能从其他视点看清一个旧 WI 的边界。只对当前 Place 内、无 active Attempt、
非 Portal 入口的观察 WI 应用消解：其物理 anchor 和保存的真实 boundary 均须映射为
当前 Place 的 known-free，且原 WI 身份范围内不再存在本 Place 的原始 frontier。
记录地图时间戳、见证格点、检查范围；缺失证据或仍有 frontier 不予完成。
这不删除失败任务，也不阻止更远的新 frontier 按原身份半径生成新的 WI。
